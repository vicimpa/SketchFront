# SKETCHFRONT — мастер-промпт для разработки игры

> Рабочее название. Этот документ — постоянная инструкция для ИИ-агента (Claude), который строит игру
> в этом репозитории. Читай его целиком в начале каждой сессии. Если решение здесь устарело —
> предложи пользователю правку документа, а не молча отступай от него.

---

## 1. Роль

Ты — ведущий геймдизайнер и ведущий разработчик браузерного командного шутера. Ты отвечаешь
за то, чтобы игра **ощущалась** хорошо (стрельба, звук, отклик), а не только работала.
Каждое решение проверяй вопросом: «станет ли от этого первые 5 минут игры веселее?»

## 2. Видение

Браузерный онлайн-шутер от третьего лица (с прицеливанием через плечо) про современную войну:
пехота и техника в одном мире, много режимов на общем ядре. Открыл ссылку — через 15 секунд
ты в бою, без установки и регистрации.

Жанровые ориентиры — общевойсковые шутеры с техникой, тактические раундовые шутеры,
королевские битвы, кооперативные зомби-режимы. **Мы делаем свою игру в этих жанрах, а не
копию конкретной**: никаких чужих названий, карт, логотипов, интерфейсов, звуков, моделей
оружия «один в один». Жанровые механики (захват точек, закладка бомбы, сужающаяся зона) — можно.

### Столпы (pillars)

1. **Пехота + техника в одной песочнице.** Сесть в машину или вертолёт должно быть так же
   естественно, как побежать.
2. **Мгновенный вход.** Ссылка → ник → бой. Загрузка первого матча < 15 с на нормальном канале.
3. **Много режимов — одно ядро.** Режим = правила + маркеры карты. Новый простой режим должен
   стоить дни, а не недели.
4. **Читаемый хаос.** Каждый выстрел ощутим: звук, отдача, трассер, хитмаркер, тряска камеры.
   Игрок всегда понимает, кто в него стреляет и откуда.

## 3. Отправная точка: что есть в репозитории

Форк [Sketchbook](https://github.com/swift502/Sketchbook) (MIT), ~8,6k строк TypeScript:

- `src/ts/characters/` — персонаж: raycast-контроллер с капсулой, стейт-машина состояний
  (`character_states/`), ИИ: `FollowPath`, `FollowTarget`, `RandomBehaviour`.
- `src/ts/vehicles/` — `Car`, `Helicopter`, `Airplane`, сиденья, двери, посадка/высадка.
- `src/ts/world/` — `World` (рендер, физика, цикл), `Scenario`, спавн-поинты, `Sky`, `Ocean`.
- **Пайплайн карт из Blender:** объекты в `.glb` несут custom properties, которые читают
  `World.ts` и `Scenario.ts`: `data: physics` (`type: box|trimesh`), `data: path`,
  `data: scenario`, `data: spawn` (`type: player|car|heli|airplane`, `driver: ai`, `first_node`).
  **Эту схему расширяем, а не заменяем** (см. §8).
- `build/assets/` — `world.glb` (26 МБ, тестовая карта), `boxman.glb`, `car.glb`, `heli.glb`,
  `airplane.glb`. Исходники — `src/blend/*.blend`.

Устарело и подлежит замене: three 0.113, webpack 4, TS 3.9, cannon.js, jQuery, sweetalert2,
dat.gui (только как dev-панель).

## 4. Технический стек

| Слой | Выбор | Почему |
|---|---|---|
| Сборка | Vite + TypeScript 5 (strict) | быстрый dev, ESM, простой конфиг |
| Рендер | three.js (актуальный) | уже используется, огромная экосистема |
| Физика | cannon-es (миграция с cannon.js) за интерфейсом `PhysicsAdapter` | минимальный порт техники; интерфейс оставляет путь на Rapier, если упрёмся в производительность |
| Навигация ботов | recast-navigation-js (navmesh из коллизий карты) | боты, зомби, заложники ходят без ручных путей |
| Частицы | three.quarks или свой GPU-инстансинг | вспышки, дым, взрывы, гильзы |
| UI | Preact + CSS поверх canvas | меню и HUD как DOM — дёшево, доступно, легко верстать |
| Звук | Web Audio API (+ three `PositionalAudio`) | 3D-звук, фильтры, реверб, без лишних зависимостей |
| Сервер | Node + Colyseus (WebSocket), комнаты и матчмейкинг | готовые комнаты/лобби, state sync; горячие данные — свой бинарный снапшот |
| Общий код | npm workspaces: `packages/shared`, `client`, `server` | правила, оружие, режимы, физика — одни на клиенте и сервере |
| Оптимизация ассетов | `@gltf-transform/cli` (meshopt/draco + KTX2) | 26 МБ карта должна стать единицами МБ |
| Хостинг | клиент — статика (Cloudflare Pages / GitHub Pages), игровой сервер — **Fly.io** | решено пользователем |
| Аккаунты и данные | Postgres (Fly Postgres или Supabase), гостевой вход + OAuth (Google/Discord) | нужны для скинов и боевого пропуска, см. §14 |

### Fly.io

- Игровой сервер — Docker-образ с `packages/server`, WebSocket через Fly Proxy (TLS терминирует Fly).
- Один процесс Colyseus на машину; при масштабировании на несколько машин — Colyseus
  с Redis-драйвером (presence/matchmaking между процессами) и sticky-маршрутизация комнаты
  на конкретную машину (`fly-replay`).
- Регион по ближайшему к основной аудитории; второй регион — когда появится онлайн.
- Бесплатного тарифа у Fly.io для новых аккаунтов нет, оплата по факту: на этапе разработки
  держать одну маленькую машину с автоостановкой (`auto_stop_machines`) и следить за счётом.

### Сетевая модель

- **Сервер авторитетен**: физика (headless), попадания, урон, правила режима — только на сервере.
- Тик сервера 30 Гц, снапшоты клиентам 20 Гц, дельта-сжатие, interest management
  (клиент получает только сущности в радиусе/видимости — обязательно для королевской битвы).
- Свой персонаж: **client-side prediction + reconciliation**. Чужие: **интерполяция** с задержкой ~100 мс.
- Техника: водитель предсказывает, пассажиры и остальные интерполируют.
- Хитскан: **lag compensation** — сервер откатывает хитбоксы на время выстрела клиента
  (критично для раундовых режимов).
- Клиент шлёт только ввод (+ направление взгляда), никогда не позицию/урон.
- Боты живут на сервере и заполняют пустые слоты в любом режиме.

## 5. Ядро геймплея (общее для всех режимов)

- **Камера:** от третьего лица, при прицеливании (ПКМ) — плечо + зум; переключение плеча.
  Опционально позже — вид от первого лица.
- **Оружие — data-driven** (`packages/shared/weapons/*.ts`): урон, спад урона по дистанции,
  множители по зонам (голова/тело/конечности), скорострельность, режимы огня, разброс,
  паттерн отдачи, магазин, перезарядка (тактическая/пустая), время прицеливания, скорость бега.
  Хитскан для стрелкового, снаряд с баллистикой — для снайперских, РПГ, гранат.
- **Целевой TTK** штурмовых винтовок 0,3–0,5 с на средней дистанции. Балансировать таблицей.
- **Здоровье:** 100 HP, регенерация после 5 с без урона (настраивается режимом), «нокдаун»
  с возможностью поднять (в командных режимах).
- **Классы** (для режимов с респауном): штурмовик (автомат, аптечки), инженер (ПП, РПГ, ремонт
  техники), поддержка (пулемёт, ящик патронов), снайпер (винтовка, маяк возрождения).
- **Техника:** HP, зоны повреждений, горение, взрыв, урон пассажирам, ремонт. Вооружение:
  пулемёт на машине, ракеты/пушка на вертолёте и самолёте.
- **Фидбек:** хитмаркер (отдельный на убийство и хедшот), индикатор направления урона,
  килфид, трассеры, вспышки, гильзы, декали попаданий, тряска камеры, звук попадания по себе.
- **Смерть:** камера на убийцу (2–3 с) → экран выбора спавна/класса.
- **Прогрессия (позже):** опыт за матч, уровни, разблокировка модулей оружия и косметики.
  Сначала в localStorage по нику, аккаунты — после запуска мультиплеера.
- **Кастомизация закладывается с M1:** персонаж и оружие собираются из слотов
  (голова, торс, ноги, снаряжение, камуфляж оружия, брелоки) с подменой мешей и материалов.
  Без этого платные скины потом придётся встраивать переделкой. Хитбоксы от скина не зависят.

## 6. Фреймворк режимов

Режим описывается конфигом и хуками в `packages/shared/modes/` (правила) и `packages/server/modes/` (логика):

```ts
interface ModeRules {
  id: string;
  teams: 'ffa' | 2;
  players: { min: number; max: number };
  respawn: 'instant' | 'wave' | 'round' | 'none';
  loadout: 'class' | 'buy' | 'loot' | 'fixed' | 'progression';
  vehicles: boolean;
  friendlyFire: boolean;
  healthRegen: boolean;
  rounds?: { toWin: number; timeSec: number; swapSidesAt?: number };
  economy?: { startMoney: number; killReward: number; roundWin: number; roundLoss: number };
  mapLayer: string;            // какой слой маркеров карты включать (см. §8)
}

interface GameMode {
  rules: ModeRules;
  onMatchStart(ctx): void;
  onPlayerJoin(ctx, player): void;
  onSpawnRequest(ctx, player): SpawnDecision;
  onDamage(ctx, event): DamageDecision;   // можно модифицировать/запретить
  onKill(ctx, event): void;
  onObjectiveEvent(ctx, event): void;      // захват, закладка, подбор флага...
  onTick(ctx, dt): void;
  checkEnd(ctx): MatchResult | null;
}
```

Общие строительные блоки (делаются один раз): зоны (сфера/объём), переносимые объекты
(бомба, флаг), раунды, экономика и закупка, инвентарь и лут, волны ботов, сужающаяся зона.

## 7. Режимы

Порядок реализации — сверху вниз. Публичная ротация на старте — 2–3 режима; остальные
доступны в приватных комнатах (по коду) — чтобы не дробить онлайн. Пустые слоты — боты.

| # | Режим | Игроки | Суть | Новые механики |
|---|---|---|---|---|
| 1 | **Командный бой** | 4–16 | Команда до N убийств | — (эталон для отладки сети) |
| 2 | **Все против всех** | 2–12 | Каждый сам за себя | — |
| 3 | **Гонка вооружений** | 2–12 | Каждое убийство меняет оружие, побеждает прошедший всю цепочку | смена оружия на лету |
| 4 | **Царь горы** | 4–16 | Удерживай точку, очки капают пока ты в ней одной командой | зона захвата |
| 5 | **Захват флага** | 6–16 | Принеси вражеский флаг на свою базу | переносимый объект |
| 6 | **Захват** (главный) | 16–32 | 3–5 точек, тикеты, техника, отряды | тикеты, отряды, спавн на точках/сквадах |
| 7 | **Штурм** | 16–32 | Атака сносит цели по секторам, оборона держит, у атаки ограничены тикеты | фазы карты, разрушаемые цели |
| 8 | **Минирование** | 2×2 – 6×6 | Раунды без респауна; атака закладывает заряд на одну из точек, оборона мешает или разминирует | раунды, экономика, закупка, бомба, компенсация лага |
| 9 | **Заложники** | 2×2 – 6×6 | Раунды; штурмовая группа выводит заложников-ботов в зону эвакуации, охрана мешает; убийство заложника — штраф | ИИ заложников (`FollowTarget`), зона эвакуации |
| 10 | **Зомби-волны** (кооп) | 1–8 | Волны нарастают, между волнами — закупка, починка баррикад, босс каждые 5 волн | спавнеры, орда на navmesh, баррикады |
| 11 | **Заражение** | 6–16 | Один зомби, каждое убийство обращает жертву; выжившие держатся до таймера | смена команды на лету |
| 12 | **Королевская битва** | 30–60 (соло/отряды) | Высадка с самолёта с парашютом, лут, сужающаяся зона, последний выживший | лут, инвентарь, парашют, зона, interest management |
| 13 | Весёлые: гонки, воздушный бой | 2–12 | Только техника | чекпоинты |

## 8. Карты

### Стратегия: «одна большая карта — много арен»

Контента на десятки отдельных карт у нас не будет. Поэтому:

- **Большая карта** (~1–2 км², остров или долина с городом, промзоной, деревней, базой,
  лесом) — для режимов «Захват», «Штурм», королевской битвы и «Гонок».
- **Малые режимы** («Минирование», «Заложники», командный бой) играют на **выгороженном районе**
  той же карты: свой слой маркеров включает барьеры, точки закладки, зоны закупки.
  Один район — одна «арена». 4–6 районов = 4–6 малых карт почти бесплатно.
- Отдельно — 1–2 маленькие компактные карты, если раундовым режимам районов не хватит.
- Тестовая карта `world.glb` из Sketchbook остаётся для разработки.

### Пайплайн

1. **Грейбокс** в Blender: кубы, рампы, укрытия. Проверяем линии видимости, тайминги
   («за сколько секунд добегают до точки B»), ширину проходов для техники.
2. **Рельеф:** реальный DEM (SRTM, public domain) через аддон BlenderGIS или
   heightmap из Tangram Heightmapper → упрощаем → лепим вручную.
3. **Модульные киты** для застройки (см. §9), скаттер растительности через geometry nodes.
4. **Маркеры геймплея** — empties с custom properties (расширение схемы Sketchbook):

   | `data` | Параметры | Назначение |
   |---|---|---|
   | `spawn` | `type: player`, `team: a\|b\|any`, `layer` | спавн игроков |
   | `spawn` | `type: car\|heli\|airplane\|...`, `team`, `respawn_sec` | техника |
   | `zone` | `zone_type: capture\|bombsite\|extraction\|buyzone\|hill\|bounds`, `id`, `radius` или меш-объём | зоны режимов |
   | `object` | `object_type: flag\|bomb\|hostage`, `team` | объекты режимов |
   | `loot` | `tier: 1..3`, `kind: weapon\|ammo\|armor\|heal` | лут королевской битвы |
   | `spawner` | `kind: zombie`, `wave_min` | спавнеры орды |
   | `barrier` | `layer` | стены, включаемые слоем режима |
   | `physics` / `path` / `scenario` | как в Sketchbook | без изменений |

   Свойство `layer` (через запятую: `tdm,bomb_a`) определяет, в каких режимах/аренах объект активен.
5. **Коллизии:** упрощённые меши `data: physics`, не трипсы рендер-геометрии.
6. **Navmesh** генерируется из коллизий на этапе сборки и кладётся рядом с картой.
7. **Экспорт → оптимизация:** `.glb` → `gltf-transform` (meshopt + KTX2, атласы) →
   разбивка на чанки по районам для потоковой загрузки большой карты.

Blender подключён через MCP: модели можно искать и импортировать из Poly Haven, Sketchfab,
Poly Pizza и генерировать уникальные пропсы (`generate_3d`) — всегда с проверкой масштаба
и записью в `CREDITS.md`.

## 9. Ассеты

### Арт-дирекшн

**Стилизованный low-poly с PBR-освещением** («полигональный милитари»): чёткие силуэты,
ограниченная палитра, сильный свет, пост-обработка (bloom, лёгкий SSAO, цветокоррекция,
туман по дистанции). Причины: огромный выбор бесплатных CC0-ассетов в этом стиле,
производительность в браузере, единство картинки. **Не смешивать** фотореалистичные модели
с low-poly — единство стиля важнее качества отдельной модели.

### Источники

**Решение пользователя: только бесплатные ассеты с открытыми лицензиями, без покупок.**
Игра коммерческая (платные скины, боевой пропуск), поэтому:

- **Предпочтительно CC0** — можно менять и продавать производные без условий.
- **CC-BY** — можно, с атрибуцией в `CREDITS.md` и на экране «Авторы».
- **Royalty-free с разрешением коммерции** (Sonniss, Mixamo, Pixabay) — можно, в рамках их условий.
- **Не брать:** CC-BY-NC (запрет коммерции), CC-BY-ND (запрет изменений), CC-BY-SA
  (share-alike плохо сочетается с продажей производных скинов), «free for personal use»,
  рипы из игр, реальное брендированное оружие и техника с логотипами.
- **Платные скины делаем сами** как производные: перекраска, новые материалы и камуфляжи,
  комбинации деталей, доработка в Blender. Продавать CC0-модель как есть формально можно,
  но игроку это видно, поэтому в магазин идёт только доработанное.
- Пользователь сам ассеты не делает: производство контента — работа агента через Blender MCP
  (импорт, сборка, перекраска, ретопология, запекание текстур). `generate_3d` может тратить
  кредиты пользователя — использовать только с его согласия.

**Звуковой дизайн** (то, что делает «крутой звук»):
- Выстрел = слои: «механика» вблизи + «тело» + «хвост» с реверберацией по окружению
  (улица/помещение) + отдельный «дальний» сэмпл после ~150 м. Вариации питча ±5%, без повторов подряд.
- Задержка звука по скорости звука для дальних выстрелов и взрывов.
- Окклюзия: low-pass, если между источником и слушателем геометрия.
- Доплер и обороты для двигателей (луп с кроссфейдом по RPM).
- Микс с приоритетами: свой выстрел и попадания по себе всегда слышны, дальние — дакаются.
- Звук-фидбек: хитмаркер, убийство, хедшот, «пуля просвистела рядом» (whiz).

## 10. Экраны и интерфейс

- **Загрузка:** прогресс, подсказки по геймплею, арт.
- **Главное меню** (3D-сцена на фоне): Играть (быстрая игра / список серверов / приватная
  комната по коду) · Режимы · Арсенал (снаряжение, модули) · Настройки · Авторы.
- **Настройки:** графика (пресеты + рендер-скейл, тени, дальность), звук (общая/эффекты/музыка/голос),
  управление (переназначение клавиш, чувствительность, инверсия, FOV), сеть (регион, пинг).
- **Лобби комнаты:** игроки, команды, режим, карта/арена, готовность.
- **Экран развёртывания:** карта с точками спавна, выбор класса и снаряжения.
- **HUD:** здоровье, патроны, прицел, миникарта/компас, цели режима, килфид, таймер/счёт,
  индикаторы урона, подсказки взаимодействия. Для королевской битвы — инвентарь и зона.
- **Таблица счёта** (Tab), **пауза** (Esc), **смерть** (камера на убийцу), **итоги раунда/матча**
  (MVP, опыт, лучшие моменты).
- **Скриншоты:** клавиша скриншота (PNG без HUD), фоторежим (свободная камера, пауза в
  одиночке), карточка итогов матча для шеринга.

## 11. Бюджеты производительности

- 60 FPS на ноутбуке среднего уровня (интегрированная графика — пресет «Низкие» ≥ 45 FPS).
- < 300 draw calls в кадре (инстансинг растительности и пропсов), < 1 млн треугольников в кадре.
- Первая загрузка до входа в матч < 25 МБ; большая карта — потоково по чанкам.
- Сеть: < 64 кбит/с на игрока в матче на 32 человека.
- Сервер: одна комната «Захвата» на 32 игрока — < 1 ядра CPU.

## 14. Монетизация

**Принцип: только косметика, никакого pay-to-win.** За деньги нельзя получить урон,
точность, здоровье, оружие раньше других или преимущество в видимости (скины не могут
быть менее заметными, чем стандартные: контур и силуэт персонажа читаются одинаково).

- **Платные скины:** персонажи (по слотам), камуфляжи оружия, брелоки, техника, эмоции,
  карточки игрока, эффекты убийства (неброские).
- **Боевой пропуск:** сезон 8–10 недель, ~50 уровней, бесплатная и премиум-ветка.
  Опыт пропуска — за игру и еженедельные задания, без жёсткого гринда. Купленный пропуск
  не сгорает частично: всё, что открыто, остаётся навсегда.
- **Без лутбоксов:** игрок всегда видит, что покупает (лутбоксы юридически рискованны
  в ряде стран и бьют по репутации).
- **Валюта:** одна премиум-валюта; пакеты кратны ценам в магазине, чтобы не оставались «хвосты».

### Техника

- Инвентарь, баланс валюты и прогресс пропуска хранятся **только на сервере** в Postgres;
  клиент ничего не начисляет сам. Покупки подтверждаются вебхуком провайдера,
  обработка идемпотентна (повторный вебхук не начисляет дважды).
- **Платёжный провайдер** — лучше merchant of record (Paddle, Xsolla и подобные): он сам
  считает налоги, НДС и возвраты по странам. Выбор зависит от страны, где зарегистрирован
  продавец; некоторые провайдеры там недоступны, поэтому решает пользователь перед M10.
- Скины — отдельные ассеты, грузятся лениво (не входят в бюджет первой загрузки §11).
